# Working on Drizziq

## Project and environment

- This is a personal, single-developer hobby app for a few known phones, with no app-store plans. Prefer quick iteration and low maintenance. Fix device-specific problems when they arise; occasional missed bugs are acceptable.
- Native Kotlin Android app with platform Views, one Activity, a Repository and pure data/parsing code. No ViewModels, use cases, Flows, coroutines or architecture-test framework. Introduce abstractions only for real behavior or tests.
- Use JDK 21, Android SDK platform 37, Build Tools 36.0.0, Python 3.11+ (standard library only) and the checked-in Gradle wrapper. The workstation has JDK 21 at `/usr/lib/jvm/java-21-openjdk` and SDK at `/home/psyke/Android/Sdk`; keep machine paths out of tracked build configuration. `local.properties` or `ANDROID_HOME` supplies the SDK path.
- `tools/verify` respects caller-provided `JAVA_HOME`, `GRADLE_USER_HOME` and `ANDROID_USER_HOME`. `--offline` needs previously downloaded dependencies; report missing dependencies separately from test failures.

## Design and assets

- One dark, sci-fi HUD palette with restrained typography/pictograms; no light mode or system-theme switching.
- Generate artwork locally or use user-supplied assets. Editable SVGs in `artwork/icons/` are the source of truth. Builds run `tools/generate_icons.py`; edit SVGs, not generated vectors or `IconAssets.kt`. Runtime code may position/tint/rotate vectors; Canvas is for dynamic charts/maps, not icon shapes. See [artwork instructions](artwork/icons/README.md). Do not download icon packs or stock assets.
- Manual icon regeneration/check: `python3 tools/generate_icons.py [--check]`. Preserve the launcher safe zone. Artwork is locally authored, adapted from the author's `todo-0` project, under the app's MIT licence.

## Data sources and behavior

- Sources must be free and public. Any account or API-key requirement, even a free registration, needs explicit user approval before integration.
- **Weather:** [DWD open data](https://opendata.dwd.de/weather/), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); [reuse terms](https://www.dwd.de/copyright). MOSMIX L uses `local_forecasts/mos/MOSMIX_L/single_stations/{id}/kml/MOSMIX_L_LATEST_{id}.kmz`. Select the nearest bundled station within 50 km, show its distance, and retain station forecasts without spatial interpolation. [Station catalogue](https://www.dwd.de/DE/leistungen/met_verfahren_mosmix/mosmix_stationskatalog.cfg?view=nasPublication&nn=16102) degrees/minutes are converted to decimal degrees in `stations.tsv` (captured 2026-10-22).
- **Forecast semantics:** Kelvin to Celsius, m/s to km/h, `PPPP` Pa to hPa. `R101` is already a 0–100 percent probability of >0.1 mm in the preceding hour; `FX1` is the preceding-hour gust, never a substituted 3/12-hour gust. Missing/invalid fields stay unknown. Humidity is displayed only when supplied. See DWD's [element definitions](https://opendata.dwd.de/weather/lib/MetElementDefinition.xml) and [weather-code workbook](https://www.dwd.de/DE/leistungen/opendata/help/schluessel_datenformate/kml/mosmix_element_weather_xls.xlsx?__blob=publicationFile&v=1).
- Today spans the selected place's local midnight through noon tomorrow, inclusive. Earlier values come from the preceding MOSMIX issue covering midnight and remain forecasts, not observations. Latest-issue values win. Preserve actual source instants in fractional-offset zones. Week aggregates merge earlier and latest issue hours with latest values winning; rain/sunshine totals require every hourly interval of a complete local day; derive each civil-date boundary independently with `atStartOfDay` for DST. Daily wind is the maximum hourly speed; condition is the most severe supplied code.
- Forecast freshness is nine hours from issue; radar is twenty minutes. Healthy automatic forecast checks use a 30-minute successful-download interval (missing/stale/failed data retries on the five-minute tick); radar polls every five minutes only while visible. Manual refresh and connectivity recovery can force both products. The header selects the nearest latest-issue hour within one hour, including a future validity; Today highlights the containing column. Offline/failed refreshes retain matching successful data and mark it stale. Loading cached data or failing a refresh must not advance the last-successful-download time. Validate zones with `java.time.ZoneId` at entry/storage; skip malformed favourite rows independently.
- **Radar:** DWD `radar/composite/rv/composite_rv_LATEST.tar`, plus observed members from the preceding twelve five-minute archives. Genuine fixtures captured 2026-10-22 use ODIM HDF5 uint32 ACRR, 1100 × 1200 pixels, WGS84 DE1200 stereographic projection. Honour gain/offset/nodata/undetect, verify validity against issue + lead, and mark historical gaps; no fabricated frames. Keep projection/input limits and versioned PNG/cache validation in the implementation and focused tests.
- **Radar screen:** Dedicated precipitation radar, restored to the v1.4.1 interaction and single playback loop. Satellite/temperature products and WMS requests are removed. Cached radar uses versioned PNG/manifest validation; decode a frame when it is needed rather than decoding the entire saved sequence before first display.
- **Basemap:** [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), ODbL, `https://tile.openstreetmap.org/{z}/{x}/{y}.png`; follow the [tile policy](https://operations.osmfoundation.org/policies/tiles/). Keep visible linked attribution and an identifying User-Agent. Request visible tiles only, cache/revalidate them conditionally after seven days; no bulk downloads. Access recency and successful receipt/validator timestamps are separate. Cache budgets and atomic writes must preserve useful retained data on failure.
- **City search:** keyless, non-commercial [Open-Meteo geocoding](https://open-meteo.com/en/docs/geocoding-api), with [GeoNames](https://www.geonames.org/) metadata under [CC BY 4.0](https://open-meteo.com/en/licence). Requests use count=10, language=de, format=json without country filtering. Valid text submits after 400 ms or keyboard Search; typing reuses warm results while keyboard Search explicitly refreshes them (still honouring Retry-After); results require explicit selection. Keep provenance through saved/edited labels, honour Retry-After, and cancel pending work on edits/dismissal/backgrounding. No persisted search history or logging of queries/full URLs/coordinates. Recheck provider terms before changing usage.
- **Location:** optional foreground coarse/fine permission and one explicit snapshot, no background tracking. Resolve stations/zones locally without reverse geocoding. Weather/tile requests still reveal station/viewport information to providers.
- **Time zones:** unchanged `timezones.tree`/`timezones.txt` from [PhotoStructure tz-lookup revision 6051e7e](https://github.com/photostructure/tz-lookup/commit/6051e7e2fe8b754e23d40aff0120cf9b38bde608), version 11.7.0, retrieved 2026-10-22. Code/port: [CC0](docs/licenses/tz-lookup-CC0.txt), originally The Dark Sky Company with PhotoStructure changes. Geography: [timezone-boundary-builder](https://github.com/evansiroky/timezone-boundary-builder), © OSM contributors, [ODbL](docs/licenses/timezone-data-ODbL-1.0.txt). The exact bundled data is publicly available in the [GitHub source](https://github.com/psyke089/drizziq/tree/main/app/src/main/assets). Lookup is approximate at borders; unresolved places get an IANA-zone prompt. Regenerate metadata with `python3 tools/update_metadata.py` (network required).
- **Sun times:** local NOAA/Meeus-style calculation of geometric solar-centre crossings at −0.833° within the selected civil day, with explicit polar/skipped-date outcomes. [NOAA equations](https://gml.noaa.gov/grad/solcalc/calcdetails.html); fixed [USNO reference](https://aa.usno.navy.mil/data/api) cases are in `SolarCalculatorTest`. These are standard-horizon times; the separate [sunset visibility/spot-finder proposal](docs/future/SUNSET.md) remains future work.
- Full attribution/licence texts live in [bundled notices](app/src/main/assets/notices.txt) and `docs/licenses/`. jHDF is MIT; its compression/logging dependencies retain MIT/Apache notices. Desugar JDK libraries use GPLv2 with Classpath Exception; [source](https://github.com/google/desugar_jdk_libs). The Gradle wrapper is build-only Apache 2.0 tooling; see [NOTICE](gradle/wrapper/NOTICE). Preserve these files when updating dependencies.

## Testing and iteration

- Practice TDD for pure behavior: write the smallest meaningful JVM regression test first when practical, observe its assertion fail, then implement. A one-line fix may take its focused test immediately afterward. Use characterization tests for refactoring existing behavior.
- While iterating, run only the affected JVM class, tooling test, phone phase or formatter. No full gate after every edit or before every handoff. Docs/formatting-only changes need no tests.
- For UI/layout/copy/SVG changes, briefly inspect the changed screen on the usual phone. Avoid tests pinning dimensions, colours, typography or incidental view structure. Device-specific problems can wait until observed. No device matrix, coverage targets, benchmarks or new test framework without a concrete need.
- Keep useful behavior tests: parsing, boundaries, missing data, cache/failure retention, time zones, cancellation and lifecycle. Do not weaken tests to hide a bug; obsolete aesthetic contracts may be removed deliberately when simplifying the suite.
- JVM: JUnit 4 in `app/src/test`, same package as the code, fixed timestamps/fixtures/fakes, no network or real sleeps. Android stubs should fail on use. Device checks: `PhoneExercise` in `app/src/androidTest`. Python: standard-library `unittest` in `tools/tests`, with fake subprocesses; never toggle phone radios to test the runner.
- Before tagging/publishing, run `./tools/verify` once and a short smoke on the usual phone. Add targeted phone checks only for the behavior changed. Connectivity-changing `--full` is an explicit opt-in, not a routine release requirement. A missing phone blocks phone verification only; report it plainly.
- Android lint and ktfmt are configured. Keep lint strict without a baseline; do not add detekt, ktlint, screenshot testing, managed emulators, MockK, Turbine or architecture tooling without a demonstrated need. Report actual checks/failures in one or two lines.

## Commands and phone use

- Local release/CI gate: `./tools/verify [--offline]` (Python tests, formatCheck, JVM tests, lint, debug/release/device-test APK builds). Kotlin formatting uses ktfmt's Kotlin style; verification never reformats automatically.
- Focused JVM: `./tools/verify --gradle-only testDebugUnitTest --tests 'app.drizziq.ReadingPolicyTest'`.
- Formatting: `./tools/verify --gradle-only formatCheck` / `./tools/verify --gradle-only formatKotlin`. Lint: `./tools/verify --gradle-only lintDebug`.
- Build phone APKs: `./tools/verify --gradle-only assembleDebug assembleDebugAndroidTest`. Install matching builds with `adb -s SERIAL install -r app/build/outputs/apk/debug/app-debug.apk` and `adb -s SERIAL install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`. The runner never installs/uninstalls apps. Reports/APKs are under ignored `app/build/`; phone logs under `tmp/verification/`.
- Phone checks: `python3 tools/verify_phone.py --serial SERIAL`; use repeatable `--phase NAME` for targeted checks, `--focused` for additional behavioral regressions, `--live` for actual providers, `--places-integration` for place/favourite persistence, and explicit `--full` for connectivity integration. Consult `--help` for maintained phases.
- Default phone checks use a fixed clock, isolated files/preferences and fixture transport that rejects unexpected HTTP. Snapshot/restore real places, favourites and map camera (including preference `.bak` files) even on failure; attempt all restorations and reopen the app. Keep radio-changing phases inside the full runner's restoration scope.
- Use an explicit serial when multiple devices are attached. Preserve app data and permissions. Never uninstall to resolve signing mismatch. Verify foreground package/current bounds before coordinate taps; prefer semantic selectors. Instrumentation may exit to the launcher.
- Debug/published APKs share `~/.android/debug.keystore`; override only through `ANDROID_USER_HOME`. Do not commit keys/passwords. Gradle release builds are unsigned build checks, not published installation artifacts.

## Remotes and releases

- Codeberg is the source of truth; push `main` to Codeberg and directly to the `github` remote (`git@github.com:psyke089/drizziq.git`). There is no push mirror. Push `main` and release tags separately, and keep tags in sync (`git push github main`, `git push github --tags`).
- `.github/workflows/ci.yml` runs the local gate on main pushes; tags `v*` also validate version/signature and publish the signed debug APK plus SHA-256. `workflow_dispatch` builds a preview; recover a missed tag run with `gh workflow run ci.yml --ref v<VERSION>`. `tools/install-android-sdk.sh` installs CI's required SDK packages.
- Published builds restore the existing key from `DRIZZIQ_KEYSTORE_B64`; keep its signing identity so upgrades retain app data. A version tag must match `versionName`.
- Refresh the README screenshot when the UI changes materially. Use a public city preset, capture raw, and restore original places/camera. No mandatory screenshot-attachment or URL-audit ritual for every release; screenshot-only updates need no app test run.
